# UC-011-ACTOR-001-EVT-011-ENT-005-IDEMPOTENT-RESULT-RETURNED-IN-PLATFORM

## Цель

Обеспечить единичный бизнес-эффект изменяющего запроса при повторах и
конкурентном выполнении.

## Применимость

Основной актор в имени — User; тот же механизм обязателен для Operator и
Administrator, REST и MCP.

## Вход

User из JWT, operation, idempotency key, канонические бизнес-параметры.

## Основной поток нового запроса

1. Построить fingerprint параметров.
2. Атомарно создать `IN_PROGRESS` в области User + operation + key.
3. Выполнить предметную транзакцию.
4. Сохранить безопасный response snapshot и `SUCCEEDED`.
5. Вернуть результат.

## Поток повтора

- совпавший fingerprint и `SUCCEEDED` — вернуть snapshot;
- отличающийся fingerprint — conflict;
- `IN_PROGRESS` — вернуть повторяемый статус без второго эффекта;
- исходная контролируемая ошибка может быть сохранена согласно контракту.

## Результат

Один ключ создаёт не более одного предметного эффекта. Запись доступна 24 часа.

## Критерии приёмки

1. Повтор возвращает тот же бизнес-результат.
2. Конфликт параметров обнаруживается.
3. Параллельные запросы не обходят ограничение.
4. Истечение записи не удаляет предметный результат.
5. Политика одинакова для REST и MCP.
