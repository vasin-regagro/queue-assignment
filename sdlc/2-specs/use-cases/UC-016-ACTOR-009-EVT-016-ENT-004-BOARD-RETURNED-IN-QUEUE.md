# UC-016-ACTOR-009-EVT-016-ENT-004-BOARD-RETURNED-IN-QUEUE

## Цель

Вернуть публичную HTML-страницу со всеми очередями и безопасным представлением
активных участников.

## Трассировка

- [PRD 0.6, US-10, FR-14, DEC-014](../../0-vibes/prd/prd.md)
- [PT-014](../../1-business-tasks/planning/PT-014.md)

- [EVT-016](../events/EVT-016-PUBLIC-QUEUE-BOARD-VIEWED-IN-QUEUE.md)
- [ENT-002](../entities/ENT-002-QUEUE-IN-QUEUE.md)
- [ENT-004](../entities/ENT-004-QUEUE-ENTRY-IN-QUEUE.md)

## Интерфейс

`GET /queues-board`, HTML (`text/html`), без JWT и без изменяющих элементов.

## Основной поток

1. Получить все Queue по возрастанию `id`.
2. Одним eager-loaded чтением получить их активные QueueEntry и User name.
3. Исключить `COMPLETED` и `CANCELLED`.
4. Отсортировать записи по `joined_at`, затем `id`.
5. Преобразовать данные в публичную read model с белым списком полей.
6. Отрисовать Blade-карточку для каждой Queue.
7. Показать статус, счётчик участников и таблицу записей.
8. Если активных записей нет, показать явное пустое состояние.
9. Добавить автоматическое обновление через 15 секунд.

## Альтернативы и ошибки

- очередей нет — показать общее пустое состояние;
- у Queue нет активных записей — Queue остаётся на странице с локальным пустым
  состоянием;
- имя User отсутствует — показать нейтральное значение `Без имени`;
- ошибка чтения — стандартный HTTP 5xx без внутренних подробностей.

## Результат

Публичный наблюдатель получает актуальный срез без изменения данных и без
доступа к закрытым полям User/QueueEntry.

## Критерии приёмки

1. JWT не требуется.
2. Отображаются `OPEN` и `CLOSED` Queue.
3. Отображаются только `WAITING`, `CALLED`, `SERVING`.
4. Порядок записей соответствует FIFO.
5. Email, `user_id`, роли и токены отсутствуют в HTML.
6. Есть пустые состояния для системы и отдельной Queue.
7. HTML содержит refresh interval 15 секунд.
8. На мобильном экране таблица остаётся читаемой через горизонтальную
   прокрутку.
