# PT-006 — Организовать последовательное обслуживание

## Карточка задачи

- **Этап:** Business tasks / Planning
- **Статус:** Planned
- **Приоритет:** P0
- **Источник:** [`../../0-vibes/prd/prd.md`](../../0-vibes/prd/prd.md), US-05–US-07 и FR-05–FR-07
- **Зависимости:** PT-001, PT-003, PT-008, PT-009

## Контекст

Оператору нужен однозначный цикл обслуживания, который соблюдает FIFO и
исключает двойной вызов одного участника.

## Цель

Обеспечить последовательный переход записи от ожидания до завершения
обслуживания.

## Основной сценарий

1. Оператор вызывает первую запись `WAITING`.
2. Запись переходит в `CALLED`.
3. Оператор начинает обслуживание: `CALLED → SERVING`.
4. Оператор завершает обслуживание: `SERVING → COMPLETED`.

## Бизнес-правила

- следующий участник выбирается строго по FIFO;
- оператор работает только с назначенными ему очередями;
- каждый переход выполняется атомарно;
- прочие переходы отклоняются;
- количество одновременных записей `SERVING` определяется PT-001;
- закрытая очередь продолжает обслуживание активных записей.

## Результаты

- согласованный операционный процесс;
- матрица разрешённых переходов;
- правила для пустой очереди и конкурентных операторов;
- критерии завершённого обслуживания.

## Критерии завершения

1. Работает цепочка `WAITING → CALLED → SERVING → COMPLETED`.
2. FIFO соблюдается.
3. Один участник не вызывается дважды.
4. Оператор не действует в неназначенной очереди.
5. Пустая очередь и недопустимый переход дают понятный результат.
6. Ошибка не оставляет частично изменённого состояния.

## Не входит в задачу

- возврат записи в предыдущее состояние;
- пропуск и повторный вызов без отдельного бизнес-решения;
- управление сменами операторов.

## Передача дальше

На этапе 2 следует создать отдельные задачи для вызова, начала, завершения,
авторизации и конкурентных проверок.
