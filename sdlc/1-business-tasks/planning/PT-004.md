# PT-004 — Обеспечить прозрачность ожидания

## Карточка задачи

- **Этап:** Business tasks / Planning
- **Статус:** Planned
- **Приоритет:** P0
- **Источник:** [`../../0-vibes/prd/prd.md`](../../0-vibes/prd/prd.md), US-03 и FR-03
- **Зависимости:** PT-003, PT-008

## Контекст

Без актуальной позиции пользователь не понимает состояние ожидания и вынужден
обращаться к персоналу.

## Цель

Дать пользователю достоверную информацию о собственной записи и позиции.

## Объём

- поиск активной записи авторизованного пользователя;
- расчёт позиции среди записей `WAITING`;
- отображение состояния вместо позиции для `CALLED`, `SERVING`, `COMPLETED` и
  `CANCELLED`;
- корректный пересчёт после вызова и отмены участников;
- защита сведений о других пользователях.

## Бизнес-правила

- позиция начинается с 1;
- порядок определяется FIFO;
- отменённые и завершённые записи не участвуют в расчёте;
- при равном времени применяется стабильный уникальный идентификатор;
- пользователь получает только собственные сведения.

## Результаты

- согласованное определение позиции;
- правила ответов для всех состояний записи;
- набор пользовательских и ошибочных сценариев.

## Критерии завершения

1. Позиция соответствует порядку ожидающих.
2. После изменений очереди возвращается актуальное значение.
3. Для записи вне `WAITING` позиция ожидания не возвращается.
4. Нельзя запросить данные чужой записи.
5. Отсутствие активной записи возвращает однозначный результат.

## Не входит в задачу

- прогноз времени ожидания;
- раскрытие полного списка участников;
- уведомления об изменении позиции.

## Передача дальше

Спецификация позиции и варианты ответа должны быть перенесены в задачи этапа 2
и последующий контракт API.
