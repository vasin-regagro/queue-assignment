# PT-007 — Предоставить работу через AI-агента

## Карточка задачи

- **Этап:** Business tasks / Planning
- **Статус:** Planned
- **Приоритет:** P0
- **Источник:** [`../../0-vibes/prd/prd.md`](../../0-vibes/prd/prd.md), US-09 и FR-09–FR-11
- **Зависимости:** PT-003, PT-004, PT-005, PT-006, PT-008, PT-009, PT-010

## Контекст

AI-агенту требуется контролируемый интерфейс выполнения операций без прямого
доступа к базе данных и без расширения прав пользователя.

## Цель

Предоставить ключевые сценарии электронной очереди через MCP с бизнес-поведением,
эквивалентным REST API.

## Инструменты MVP

- `list_queues`;
- `join_queue`;
- `get_current_position`;
- `cancel_queue_entry`;
- `call_next_user`;
- `start_service`;
- `complete_service`.

## Бизнес-правила

- агент действует от имени пользователя из доверенного контекста;
- права определяются ролью пользователя, а не агентом;
- REST и MCP используют один набор бизнес-правил;
- изменяющие инструменты принимают `idempotencyKey`;
- инструменты не предоставляют произвольные запросы к базе данных;
- административные инструменты добавляются только по решению PT-001.

## Результаты

- подтверждённый перечень MCP-инструментов;
- понятные агенту успешные результаты и ошибки;
- правила передачи пользовательского контекста;
- критерии эквивалентности REST и MCP;
- готовность к контрактной декомпозиции.

## Критерии завершения

1. Назначение каждого инструмента однозначно.
2. Нельзя подменить пользователя параметрами инструмента.
3. Проверки ролей нельзя обойти через MCP.
4. Одинаковые операции REST и MCP дают одинаковый бизнес-результат.
5. Повторы изменяющих инструментов идемпотентны.
6. Каждый вызов передаётся в аудит.

## Не входит в задачу

- создание пользовательского чат-интерфейса;
- выбор конкретной LLM;
- выдача агенту прямого доступа к данным.

## Передача дальше

Каждый инструмент должен получить отдельную задачу и спецификацию контракта со
ссылкой на PT-007 и соответствующую предметную задачу.
