# queue_assignment

## Обзор проекта

`queue_assignment` — MCP-сервис для управления электронной очередью.

Сервис предоставляет REST API и MCP-инструменты, позволяя пользователям и операторам работать с очередью напрямую или через AI-агента. AI-агент использует MCP для вызова инструментов сервиса, не имея прямого доступа к базе данных.

## Цель проекта

Разработать минимальный сервис электронной очереди с поддержкой AI-агентов, обеспечивающий безопасную запись пользователей в очередь и управление её состоянием.

## Основные возможности

* создание, открытие и закрытие очередей;
* постановка пользователя в очередь;
* получение текущей позиции;
* отмена записи;
* вызов следующего пользователя;
* начало и завершение обслуживания;
* доступ к операциям через MCP;
* авторизация и проверка прав пользователей.

## Минимальные требования

Сервис должен:

* предоставлять REST API и MCP-инструменты;
* использовать общую бизнес-логику для REST и MCP;
* определять пользователя по токену авторизации;
* проверять права доступа перед выполнением операций;
* поддерживать идемпотентность изменяющих запросов;
* выполнять операции изменения очереди атомарно;
* вести журнал вызовов MCP-инструментов.

## Доменные сущности

* `Queue` — очередь.
* `QueueEntry` — запись пользователя.
* `McpToolCall` — журнал вызовов MCP.

Внешние сущности:

* `User`
* `AiAgent`

## Пользовательские роли

**Пользователь**

* запись в очередь;
* просмотр позиции;
* отмена своей записи.

**Оператор**

* вызов следующего пользователя;
* начало и завершение обслуживания.

**Администратор**

* создание, открытие и закрытие очередей.

**AI-агент**

* вызывает MCP-инструменты от имени авторизованного пользователя.

## Состояния

### Queue

* `OPEN`
* `CLOSED`

### QueueEntry

* `WAITING`
* `CALLED`
* `SERVING`
* `COMPLETED`
* `CANCELLED`

## MCP-инструменты

* `list_queues`
* `join_queue`
* `get_current_position`
* `cancel_queue_entry`
* `call_next_user`
* `start_service`
* `complete_service`

Все изменяющие инструменты используют `idempotencyKey`.

## Основные бизнес-правила

* очередь работает по принципу FIFO;
* пользователь может иметь только одну активную запись в очереди;
* номер талона уникален в пределах очереди;
* запись возможна только в открытую очередь;
* пользователь может изменять только собственные записи;
* операции обслуживания доступны только оператору;
* AI-агент не может обходить проверки авторизации и бизнес-правила.

## Развёртывание

Проект должен полностью работать в Docker.

Запуск выполняется одной командой:

```bash
docker compose up -d
```

Минимальный состав контейнеров:

* `app`
* `nginx`
* `db`
* `redis`

После запуска приложение должно быть готово к выполнению миграций, запуску тестов и работе MCP-сервера через публичный HTTPS-адрес.
