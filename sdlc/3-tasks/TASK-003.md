## Цель

Реализовать регистрацию, вход и гостевую сессию с безопасной выдачей JWT.

## Объём

- REST endpoints регистрации и входа;
- endpoint создания гостевого пользователя;
- подписание и проверка JWT;
- гостевой `exp` ровно через 24 часа;
- authentication middleware;
- безопасное хранение credentials;
- обработка истёкших, некорректных и отозванных токенов.

## Требования реализации

1. `sub` содержит User ID.
2. Роли загружаются сервером и не принимаются от клиента.
3. JWT/credentials не попадают в логи и ошибки.
4. Истечение гостевого JWT не удаляет QueueEntry.
5. Срок постоянного токена и механизм отзыва фиксируются в конфигурации и
   документации.

## Критерии приёмки

1. Регистрация и валидный вход выдают JWT.
2. Гостевой режим создаёт временного User и токен на 24 часа.
3. Защищённый route восстанавливает User из JWT.
4. Истёкший/поддельный токен отклоняется.
5. Клиент не может назначить себе роль.

## Проверки

Feature tests всех трёх потоков, JWT expiry, invalid signature и secret
redaction.
