## Ответы на открытые вопросы

1. **Какой формат токена используется и кто его выпускает?**  
   Сервис поддерживает регистрацию пользователей и выдаёт JWT access token. Также доступен гостевой режим: сервис создаёт временного пользователя и выдаёт гостевой JWT сроком на 24 часа.

2. **Может ли пользователь одновременно состоять в разных очередях?**  
   Да. Разрешена одна активная запись в каждой очереди.

3. **Как оператор назначается на очередь?**  
   Администратор назначает оператора на одну или несколько очередей.

4. **Сколько записей может одновременно находиться в `SERVING` в одной очереди?**  
   Не более одной записи на каждого оператора. В очереди одновременно может обслуживаться несколько пользователей.

5. **Можно ли отменять запись после перехода в `CALLED`?**  
   Да. Отмена разрешена в состояниях `WAITING` и `CALLED`.

6. **Когда сбрасывается нумерация талонов?**  
   В MVP нумерация не сбрасывается и увеличивается последовательно в пределах очереди.

7. **Какие пользовательские данные разрешено показывать оператору?**  
   Только номер талона, статус, время записи и отображаемое имя пользователя.

8. **Какой транспорт MCP используется?**  
   MCP Streamable HTTP.

9. **Где завершается HTTPS?**  
   На Nginx.

10. **Каковы ожидаемые объёмы очередей и запросов?**  
    До 100 очередей, до 1000 активных записей в очереди и до 20 запросов в секунду.

11. **Как долго хранятся записи, результаты идемпотентности и MCP-журнал?**  
    Записи — 90 дней, результаты идемпотентности — 24 часа, журнал MCP — 30 дней.

12. **Нужны ли административные MCP-инструменты в MVP?**  
    Нет. Административные операции доступны только через REST API.

## 10. Подключение MCP к Codex

### Пользователь

как создать коннектор для работы с сервисом из codex?

### Codex — промежуточное сообщение

Использую навык официальной документации OpenAI: сверю актуальный способ подключения MCP-сервиса к Codex и адаптирую конфигурацию под ваш `/api/mcp`.

### Codex — ответ

Ваш сервис уже является MCP Streamable HTTP-сервером. Для подключения к Codex нужно зарегистрировать URL `/api/mcp` и передать JWT как Bearer token.

### 1. Получить JWT

Для пользователя:

```bash
export QUEUE_MCP_TOKEN="$(
  curl -ksS https://localhost:8443/api/auth/login \
    -H 'Content-Type: application/json' \
    -d '{"email":"admin@example.test","password":"change-me-admin"}' \
  | jq -r '.data.accessToken'
)"
```

Либо гостевой токен на 24 часа:

```bash
export QUEUE_MCP_TOKEN="$(
  curl -ksS https://localhost:8443/api/auth/guest \
    -H 'Content-Type: application/json' \
    -d '{"name":"Codex Guest"}' \
  | jq -r '.data.accessToken'
)"
```

Обычный access token сейчас живёт 1 час, гостевой — 24 часа.

### 2. Зарегистрировать MCP-сервер

```bash
codex mcp add queue-assignment \
  --url https://localhost:8443/api/mcp \
  --bearer-token-env-var QUEUE_MCP_TOKEN
```

Проверить конфигурацию:

```bash
codex mcp list
codex mcp get queue-assignment
```

После этого перезапустите Codex или создайте новую задачу.

Эквивалентная ручная конфигурация в `~/.codex/config.toml`:

```toml
[mcp_servers.queue-assignment]
enabled = true
required = true
url = "https://localhost:8443/api/mcp"
bearer_token_env_var = "QUEUE_MCP_TOKEN"
startup_timeout_sec = 10
tool_timeout_sec = 60
```

Codex поддерживает для удалённых MCP-серверов Streamable HTTP и передачу Bearer-токена через переменную окружения. Это описано в официальных разделах [MCP](https://learn.chatgpt.com/docs/extend/mcp) и [конфигурации Codex](https://learn.chatgpt.com/docs/config-file/config-reference).

### Важный момент с локальным HTTPS

Сейчас Nginx использует самоподписанный сертификат. `curl -k` его принимает, но Codex, скорее всего, отклонит как недоверенный.

Для полноценного подключения нужен один из вариантов:

- установить локально доверенный сертификат через `mkcert` и подключить его к Nginx;
- использовать публичный домен с сертификатом Let’s Encrypt;
- только для локальной разработки добавить отдельный HTTP endpoint без перенаправления.

Для Codex Desktop на macOS переменная из терминала может быть недоступна приложению. Её можно передать окружению GUI перед перезапуском Codex:

```bash
launchctl setenv QUEUE_MCP_TOKEN "$QUEUE_MCP_TOKEN"
```

Не записывайте JWT непосредственно в `config.toml`. Для стабильного production-коннектора текущую часовую JWT-аутентификацию лучше заменить OAuth либо отдельным отзываемым service token.
